# Unit Converter UI v2.0.0

This release migrates the UI and its Python HTTP adapter to
`nist-unit-converter` 2.0.0 and catalog schema 3, while consolidating the final
catalog presentation, runtime cleanup, and release tooling into the same UI
2.0.0 release.

## Highlights

- Uses stable unit IDs for From/To values, API requests, defaults, and saved
  Favorites while displaying canonical unit names.
- Builds Category and Measure controls from the package's direct UI taxonomy
  APIs instead of deriving UI placement from NIST categories.
- Loads backend-compatible units after every From selection and limits the To
  selector to valid targets in the current Measure.
- Exposes all 462 backend units in a left-aligned Category / Unit table, with the
  five unmapped units kept in a separate `Uncategorized` filter.
- Alphabetizes API unit arrays and From/To selectors by canonical display name,
  then orders the Units table by Category and Unit name.
- Removes unreachable pre-v2 modules and unused runtime code without changing
  the documented HTTP API contract.
- Returns JSON 404 responses for unknown API paths instead of SPA HTML.

## Backend Upgrade

- Distribution: `nist-unit-converter` 2.0.0.
- Python import: `unit_converter`.
- Cloud dependency: the backend repository's immutable `v2.0.0` Git tag.
- Local dependency: `nist_unit_converter-2.0.0-py3-none-any.whl`.
- Catalog schema: version 3.
- Unit coverage: 462 total, 457 UI-mapped, and 5 unmapped.
- Favorites storage schema: version 2.

The adapter uses only public package APIs. It does not read package JSON files
or the removed physical-quantity source file directly.

## API Behavior

- `/api/catalog` returns stable IDs, canonical names, aliases, direct UI
  categories, and a separate unmapped-unit list.
- `/api/units?compatibleWith=<unit_id>` returns canonical compatible-unit
  records for the selected source.
- `/api/convert` accepts stable IDs and serializes its `Decimal` result as a
  string.
- Unknown units return `UNIT_NOT_FOUND`, incompatible quantities return
  `INCOMPATIBLE_UNITS`, and other package conversion errors return
  `CONVERSION_FAILED`.
- Unknown `GET /api/...` paths return a JSON 404 response.

## Catalog And Converter UI

- From and To controls show canonical `display_name` values while their internal
  values and conversion requests use stable `unit_id` values.
- Unit arrays are ordered without case or accent distinctions and treat
  punctuation as word separators; stable IDs break remaining ties.
- The Units table is ordered first by its full UI Category path and then by Unit
  name within each Category.
- Units use direct `ui_categories`; NIST categories are not used to infer UI
  placement. The five unmapped records remain under `Uncategorized`.
- The Units page title is concise, and the completed conversion label is
  `result`.

## Favorites Upgrade

New Favorites use schema 2 and persist `fromUnitId` and `toUnitId`. On first
load, the UI migrates schema 1 Favorites by matching their historical unit
strings against canonical display names and aliases. Valid entries are written
to the new storage key automatically; no server-side migration is needed.

## Cleanup And Tooling

- Deleted the unused `CategoryGrid`, `UnitSearch`, and `PopularConversions`
  modules, along with their unreferenced styles and design token.
- Removed obsolete wrappers, callbacks, exports, duplicate converter state,
  repeated redraw work, and an unnecessary backend index helper.
- Stored preferred conversion pairs directly as stable unit IDs.
- Aligned `npm run dev`, `npm run test:api`, and `npm run check:api` with the
  repository-local `.venv` and wheel-backed development workflow.
- Updated the README and version check to match the final runtime and release
  structure.

## Verification

- 18 adapter unit and integration tests pass, covering schema 3 totals, direct

- Browser smoke checks pass for conversion, swap, Favorites, Units, About,

## Upgrade And Rollback

- Run the local setup script again so the environment installs the new wheel.
- The setup script removes the renamed pre-v2 distribution before force-
  reinstalling the v2 wheel, including when `.venv` is reused.
- Browser Favorites migrate automatically when the v2 catalog loads.
- Deployments must install from the `v2.0.0` Git tag or matching GitHub Release
  wheel; do not rely on a PyPI release.
- To roll back, redeploy the immutable `v1.1.0` UI tag and its matching backend
  environment. The new schema 2 Favorites key can remain in browser storage;
  v1.1.0 ignores it.
